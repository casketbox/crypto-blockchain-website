# tovus.jp — WordPress サイト

さくらのレンタルサーバ（`www2799.sakura.ne.jp`）で公開する、独自ドメイン **tovus.jp** の WordPress サイトです。
テーマとプラグインを一から作っています。

| フォルダ | 内容 |
|---|---|
| `themes/tovus/` | ブロックテーマ本体。管理画面の「外観 → エディター」から、ヘッダー・フッター・各テンプレートをすべて編集できます |
| `plugins/tovus-core/` | 機能プラグイン。「用語集」投稿タイプ、初期設定、基本的なセキュリティ設定 |
| `docker-compose.yml`, `bin/` | 手元のパソコンで動作確認するための環境 |

## サイトの構成

- **トップページ**（固定ページ「ホーム」）: 次のパターンを並べています。ブロックとして自由に書き換えられます。
  ヒーロー（パララックス）→ ブロックチェーンとは → 暗号通貨とは → 3つの原理 → 活用事例 → 安全に使うために → 最新の記事 → 締めのCTA
- **ブログ**（`/blog/`）: 投稿の一覧。
- **用語集**（`/glossary/`）: 管理画面の「用語集」から用語を追加すると、五十音順の一覧と個別ページができます。
- **テンプレート**: 投稿、固定ページ、アーカイブ、検索、404、ランディング（タイトルなし・全幅）

パターンは、ブロック挿入画面の「パターン → tovus」からいつでも追加できます。
ボタンには「コイン」「スタンプ」「チェーンリンク」、グループには「カード」のスタイルがあります。

### プラグインが有効化時に行うこと

すでに設定されている項目は上書きしません。

- 固定ページ「ホーム」「ブログ」を作り、ホームをトップページに、ブログを投稿ページに設定する
- パーマリンクを「投稿名」（`/%postname%/`）にする
- テーマ同梱のロゴとサイトアイコンをメディアに登録して設定する
- 用語集が空であれば、基本の用語を 6 つ登録する

有効化中はさらに次の設定が働きます。

- XML-RPC の無効化
- WordPress のバージョン表記を HTML から削除
- 未ログインの利用者には REST API でユーザー一覧を返さない
- `?author=1` 形式でのユーザー名の推測を防ぐ

## さくらのレンタルサーバでの公開手順

### 1. ドメイン tovus.jp をサーバーに追加する

1. さくらのコントロールパネルにログインし、「ドメイン/SSL」→「ドメイン/SSL」→「ドメイン新規追加」を選びます。
2. tovus.jp をさくらで取得した場合は「さくらのドメインを使う」を、他社で取得した場合は「他社で取得したドメインを移管せずに使う」を選びます。
   - 他社で取得した場合は、そのドメイン会社の管理画面で、ネームサーバーを `ns1.dns.ne.jp` と `ns2.dns.ne.jp` に変更します。
3. 追加が終わったら、tovus.jp の「設定」で**公開フォルダ**を決めます（例: `/home/<アカウント名>/www/tovus`）。
4. 同じ画面で**無料SSL**（Let's Encrypt）を設定します。発行まで数十分かかることがあります。

### 2. WordPress をインストールする

1. 「Webサイト/データ」→「クイックインストール」→「WordPress」を選びます。
2. インストール先のURLに `tovus.jp` を、フォルダに手順 1-3 の公開フォルダを指定します。
3. データベースは「新規作成」を選びます（MySQL 8.0）。
4. 「スクリプト設定」で PHP を **8.2 以上**にしておきます。
5. `https://tovus.jp/wp-admin/` にアクセスして、管理者アカウントを作成します。
6. 「設定 → 一般」で、「WordPress アドレス」と「サイトアドレス」がどちらも `https://tovus.jp` になっていることを確認します。

### 3. テーマとプラグインを入れる

**方法 A: 管理画面から zip をアップロードする（最初の1回におすすめ）**

1. このリポジトリで `./wordpress/bin/build-zips.sh` を実行すると、`wordpress/dist/` に `tovus.zip` と `tovus-core.zip` ができます。
2. 「外観 → テーマ → 新規追加 → テーマのアップロード」で `tovus.zip` をアップロードし、**有効化**します。
3. 「プラグイン → 新規追加 → プラグインのアップロード」で `tovus-core.zip` をアップロードし、**有効化**します。

> **必ずテーマを先に有効化してください。** プラグインは有効化するときに、テーマのパターンと画像を使ってトップページを作ります。

**方法 B: GitHub Actions で自動デプロイする（2回目以降の更新に）**

`main` ブランチに `wordpress/` の変更を push すると、`.github/workflows/deploy-sakura.yml` がテーマとプラグインをサーバーに rsync します。
SSH はスタンダードプラン以上で使えます。

1. 手元のパソコンで、デプロイ専用の鍵を作ります。

   ```bash
   ssh-keygen -t ed25519 -C "github-deploy" -f ./sakura_deploy -N ""
   ```

2. 公開鍵（`sakura_deploy.pub`）をサーバーに登録します。

   ```bash
   ssh <アカウント名>@www2799.sakura.ne.jp    # サーバーのパスワードでログイン
   mkdir -p ~/.ssh && chmod 700 ~/.ssh
   echo "（sakura_deploy.pub の中身）" >> ~/.ssh/authorized_keys
   chmod 600 ~/.ssh/authorized_keys
   ```

3. GitHub のリポジトリで「Settings → Secrets and variables → Actions」を開き、次を登録します。

   | 種類 | 名前 | 値 |
   |---|---|---|
   | Secret | `SAKURA_SSH_KEY` | `sakura_deploy`（秘密鍵）の中身すべて |
   | Secret | `SAKURA_USER` | さくらのアカウント名 |
   | Variable | `SAKURA_WP_PATH` | WordPress のフォルダ（例: `/home/<アカウント名>/www/tovus`） |

4. 「Actions → Deploy WordPress to Sakura → Run workflow」を実行するか、`main` に push するとデプロイされます。
   Secrets が未設定のあいだは、構文チェックだけを行いデプロイはスキップします。

### 4. 公開後の確認

- 「設定 → 表示設定」で、トップページが「ホーム」、投稿ページが「ブログ」になっていること
- `https://tovus.jp/glossary/` で用語集が表示されること（404 になる場合は、「設定 → パーマリンク」で何も変えずに「変更を保存」を押す）
- 「設定 → 一般」で、サイトのタイトルとキャッチフレーズを設定する
- 検索エンジンに表示させる準備ができたら、「設定 → 表示設定」の「検索エンジンでの表示」のチェックを外す

### トラブルシューティング

- **ブロックエディターで保存すると「更新に失敗しました」と表示される**
  さくらの **WAF** が編集内容を攻撃と誤って判断していることがあります。
  コントロールパネルの「セキュリティ → WAF」でログを確認し、必要であれば tovus.jp の WAF を一時的に無効にしてください。
- **画像のアップロードに失敗する**
  「スクリプト設定」の php.ini で、`upload_max_filesize` と `post_max_size` を大きくしてください。

## 手元で動作確認する（Docker）

```bash
cd wordpress
docker compose up -d
./bin/local-setup.sh
```

<http://localhost:8080> で表示を確認できます。管理画面は `/wp-admin/`（ユーザー名 `admin`、パスワード `admin`）です。
`themes/` と `plugins/` はコンテナにマウントしているので、ファイルを保存するとそのまま反映されます。
終了は `docker compose down`、データごと消す場合は `docker compose down -v` です。
